# 構成図の状態表現レビュー（v0.5.42 → 改善案）

対象：全10シナリオ。2026-11-24。
目的：機器の表示色、通信経路の色、操作結果の関係を混同させない。

## 表示原則

- **機器ノードの赤**：その機器に関わる不正アクセス・実行・情報取得などの履歴があること。機器そのものが必ずマルウェア感染したことは意味しない。
- **通信経路の赤**：その経路を不正操作・攻撃の一部として通過した履歴。後段の別操作を拒否しても過去の通過線は赤のまま残す。
- **緑の×**：通信や操作の要求をその地点で拒否した事実。通信に紐づかない操作（暗号化ファイル書込）は、架空の緑の通信線を作らず、独立した操作拒否の札を付ける。
- **灰色**：未実行・未到達。先行拒否によって未到達になった工程を、同時に「阻止済み」とは表示しない。
- **復旧**：攻撃や流出の過去履歴とは別。バックアップの存在だけで「復旧済み」とはしない。

## シナリオごとの確認

| シナリオ | 成立を示す対象 | 阻止できる対象 | 混同しやすい点／レビュー観点 |
|---|---|---|---|
| 01-A VPN直接 | VPN認証、共有読取、VPN経由取得 | MFA、内部FW、読取ACL、書込ACL、Server EDR | 書込拒否は過去の読取・流出を消さない。PC EDRとSWGは直接VPN取得の経路外 |
| 01-B メール添付 | メール配送、PC実行、共有アクセス、外部送信 | メール隔離、PC EDR、内部FW、各ACL、SWG/DLP | PCの隔離とFile Serverの書込拒否は別事象 |
| 02 SaaSフィッシング | PW取得、IdP不正ログイン、SaaS閲覧、外部共有 | メール、MFA、条件付きアクセス、SaaS権限、共有ポリシー、SaaS DLP | 外部共有成立とファイル実取得は別。STEP06は調査案内で自動回復ではない |
| 03-A 委託先 | 委託先ID窃取、VPNログイン、特権、閲覧、転送 | MFA、PAM、内部FW、読取ACL、転送制限 | VPN認証が成立しても後段ファイル転送は拒否可能 |
| 03-B 更新 | 配布元侵害または途中改ざん、導入、実行、共有アクセス、流出 | 署名強制、導入保留、EDR、内部FW、ACL、出口制御 | 正規署名の確認は更新ファイルの無害性を保証しない |
| 04 SQLi | HTTP到達、WAF通過、SQL実行、DB参照、HTTP応答 | WAF、パラメータ化SQL、DB権限 | 通信許可は脆弱性成立でもDB閲覧成功でもない |
| 05 DDoS | 大量通信、回線飽和、正常アクセス障害 | 上流緩和 | 可用性低下はWebサーバー侵害を意味しない |
| 06 BEC | PW盗用、不正ログイン、メール閲覧、ルール作成、送信 | MFA、端末条件、セッション失効、送信保留 | メール送信を止めても既存の閲覧・ルール変更は残る |
| 07 内部不正 | 正規ログイン、機密閲覧、端末保存、外部アップロード | RBAC、端末保存制限、SWG/CASB、DLP | 認証成功自体は不正行為の防止失敗ではない |
| 08 AIアプリ | 未信頼文書の取得、誤採用、API応答、ツール要求、外部送信 | 文書API認可、タスク単位ツール認可、出口制御 | 正規GETのデータ取得と不正GETの外部要求は別。API応答はAPI侵害とは限らない |

## 今回の修正範囲

01-A/01-Bの「共有ファイル書込制限」単独ONを起点に、次の表示を統一する。

1. File Serverの赤いノード／赤い通過線は、過去の読取・流出履歴として維持する。
2. STEP05以降、書込ACLで暗号化が拒否された事実を、File Serverの近くに緑の「書込拒否・暗号化阻止」として示す。
3. 図の凡例には「通信遮断」と「操作拒否」を分けて記載する。
4. ノードの説明は「閲覧履歴あり・書込拒否」とし、赤い色がファイル暗号化成功を意味しないことを明らかにする。
5. ブラウザーテストでは01-A/01-Bともに、File Serverの赤いアクセス履歴と緑の書込拒否札が共存することを検証する。

## 別PRで扱う候補

- 10シナリオ全体で、ノード色が「機器の感染」ではなく「その地点で観測された出来事」であることをツールチップ・凡例に統一する。
- 書込権限を後から変更した際にも、過去の読取・流出記録と変更後の操作拒否が分離していることを、全シナリオ横断のUIテストへ追加する。
- スクリーンショット目視レビューで長い札や矢印との重なりがないことを確認する。

## 公開判定

作業ブランチで検証。既存10シナリオ・39対策の判定ロジックは変更しない。
ブラウザーテストに合格した後も、今回の視覚表現の変更はドラフトPRでレビューし、mainへの直接反映はしない。
